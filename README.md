# Uber Fare Prediction — MLOps Pipeline

A production-grade MLOps pipeline for predicting NYC taxi fares. The pipeline covers the full lifecycle: raw data ingestion, feature engineering, model training with experiment tracking, automated quality gating, model registry promotion, containerization, and Kubernetes deployment — all governed by a GitHub Actions CI/CD workflow.

---

## Architecture Overview

```
Raw Data (DagsHub S3)
        │
        ▼
  Data Ingestion          ← splits into train/test sets
        │
        ▼
 Data Preprocessing       ← cleans outliers, handles nulls
        │
        ▼
 Feature Engineering      ← Haversine distance, datetime decomposition, StandardScaler
        │
        ▼
  Model Training          ← DecisionTreeRegressor, logs to MLflow
        │
        ▼
 Model Evaluation         ← R² computed, stored in reports/metrics.json
        │
        ▼
 Model Registration       ← pushed to MLflow Registry (Staging stage)
        │
        ▼
  Quality Gate            ← CI fails if R² < 0.50
        │
        ▼
 Model Promotion          ← Staging → Production in MLflow Registry
        │
        ▼
  FastAPI Service         ← serves predictions with Prometheus metrics
        │
        ▼
 Docker → ECR → EKS       ← containerized, deployed to Kubernetes
        │
        ▼
 Prometheus & Grafana     ← scrapes metrics and visualizes dashboards
```

### What is tracked by Git vs DVC

| Path | Tracked by | Reason |
| :--- | :--- | :--- |
| `src/`, `app/`, `scripts/`, `tests/` | Git | Source code — changes must be versioned |
| `params.yaml`, `dvc.yaml` | Git | Pipeline config — changes trigger reruns |
| `data/raw/uber.csv.dvc` | Git | DVC pointer file — not the data itself |
| `data/raw/uber.csv` | DVC (S3) | 22MB file — too large for Git |
| `data/processed/**` | DVC | Pipeline-generated, reproducible from source |
| `models/model.pkl` | DVC | Pipeline-generated, reproducible from source |
| `models/scaler.pkl` | DVC | Pipeline-generated, reproducible from source |
| `.env` | Neither | Contains secrets — gitignored |
| `mlflow.db` | Neither | Local MLflow DB — gitignored |

## Pipeline Stages

All stages are defined in `dvc.yaml` and run via `dvc repro`. Each stage declares its inputs, outputs, and parameters explicitly — DVC only reruns a stage when its declared dependencies change.

### 1. Data Ingestion

**Script:** `src/data/data_ingestion.py`

Reads the raw `uber.csv` from DVC-tracked storage and splits it into `train.csv` and `test.csv` using an 80/20 split.

**Why:** Separating data loading from preprocessing keeps the pipeline modular. The split is reproducible via `random_state: 42` in `params.yaml`.

```yaml
# params.yaml
data_ingestion:
  test_size: 0.2
  random_state: 42
```

---

### 2. Data Preprocessing

**Script:** `src/data/data_preprocessing.py`

Cleans the raw data: removes null values, drops records with invalid coordinates (outside continental US), and filters out fare outliers.

**Why:** Raw NYC taxi data contains corrupt GPS readings (0,0 coordinates) and extreme fares. These must be removed before feature engineering or they distort the model.

---

### 3. Feature Engineering

**Script:** `src/features/feature_engineering.py`

Derives the following features from raw coordinates and timestamps:

| Feature | Description |
| :--- | :--- |
| `dist_km` | Great-circle distance between pickup and dropoff (Haversine formula) |
| `hour` | Hour of day (captures peak demand patterns) |
| `day` | Day of month |
| `month` | Month (captures seasonal patterns) |
| `year` | Year |
| `dayofweek` | Day of week (0=Monday, 6=Sunday) |
| `passenger_count` | Number of passengers |

A `StandardScaler` is fitted on the training data and saved to `models/scaler.pkl`. The same scaler is applied to the test set and used at inference time. The scaler is never fitted on test data to prevent leakage.

**Outputs:** `train_final.csv`, `test_final.csv`, `models/scaler.pkl`

---

### 4. Model Building

**Script:** `src/models/model_building.py`

Trains a `DecisionTreeRegressor` with hyperparameters defined in `params.yaml`:

```yaml
model_building:
  max_depth: 10
  max_leaf_nodes: 32
  random_state: 10
```

The trained model is saved to `models/model.pkl`.

**Why a Decision Tree?** Interpretable, fast to train, and sufficient for this feature set. The `max_depth` and `max_leaf_nodes` constraints prevent overfitting.

---

### 5. Model Evaluation

**Script:** `src/models/model_evaluation.py`

Evaluates the model on the held-out test set. Computes R², RMSE, and MAE. Results are written to `reports/metrics.json` and tracked by DVC as a metric.

MLflow is used to log all metrics and parameters for experiment comparison on DagsHub.

**Output:** `reports/metrics.json`, `reports/experiment_info.json`

---

### 6. Model Registration

**Script:** `src/models/register_model.py`

Reads `experiment_info.json` to identify the run ID of the just-trained model. Registers it to the MLflow Model Registry under the name `UberFareRegressor` in the `Staging` stage.

**Why register to Staging first?** Staging is a holding area. The model must pass quality tests before being promoted to Production. This prevents a broken model from ever serving live traffic.

---

## Quality Gate

**Script:** `tests/test_model.py`

Loads the latest `Staging` model from the MLflow Registry and runs three assertions:

1. **Model loads** — the artifact is accessible and deserializable.
2. **Model signature** — the model accepts a 7-feature input and returns a prediction.
3. **Model performance** — R² on the test set must be ≥ 0.50.

```python
expected_r2 = 0.50
self.assertGreaterEqual(r2, expected_r2, ...)
```

If any assertion fails, the CI pipeline stops. `promote_model.py` is never called. The bad model stays in Staging and never reaches Production.

**Why this threshold?** R² = 0.50 means the model explains at least 50% of fare variance, which is a minimum bar for a useful fare predictor. Adjust in `test_model.py` as the model improves.

---

## Model Promotion

**Script:** `scripts/promote_model.py`

Promotes the latest `Staging` model to `Production` in the MLflow Registry. Archives any previously `Production` model.

This script only runs in CI after the quality gate passes. Locally it uses DagsHub OAuth. In CI it uses the `CAPSTONE_TEST` token for non-interactive authentication.

```python
# Auth pattern: token in CI, OAuth locally
dagshub_token = os.getenv("CAPSTONE_TEST")
if dagshub_token:
    os.environ["MLFLOW_TRACKING_USERNAME"] = dagshub_token
    os.environ["MLFLOW_TRACKING_PASSWORD"] = dagshub_token
else:
    dagshub.init(...)  # browser OAuth for local development
```

## FastAPI Service

**File:** `app/main.py`

Serves predictions via HTTP. Loads the scaler and model during the FastAPI `lifespan` startup event — not at module import time. This is critical: it prevents DagsHub OAuth from triggering during test collection, which would hang the CI runner.

### Endpoints

| Method | Path | Description |
| :--- | :--- | :--- |
| `GET` | `/` | Web UI (Leaflet.js map, input form) |
| `POST` | `/predict` | Accepts form data, returns predicted fare |
| `GET` | `/metrics` | Prometheus metrics scrape endpoint |

### Request Parameters (`/predict`)

| Field | Type | Description |
| :--- | :--- | :--- |
| `pickup_datetime` | string | ISO format datetime |
| `pickup_longitude` | float | Pickup GPS longitude |
| `pickup_latitude` | float | Pickup GPS latitude |
| `dropoff_longitude` | float | Dropoff GPS longitude |
| `dropoff_latitude` | float | Dropoff GPS latitude |
| `passenger_count` | int | Number of passengers |

### Prometheus Metrics

Three custom metrics are exposed at `/metrics`:

- `app_request_count` — total requests by method and endpoint
- `app_request_latency_seconds` — request latency histogram by endpoint
- `model_prediction_fare_amount` — distribution of predicted fares

## CI/CD Pipeline

**File:** `.github/workflows/ci.yaml`

The pipeline runs on every push or pull request to `main`. Each step is conditioned on the previous step's success — a failure at any stage stops the pipeline.

```
Checkout → Setup Python → Install uv → Install Dependencies
    ↓
Configure DVC Remote (DagsHub S3)
    ↓
Pull Raw Data (dvc pull)
    ↓
Run DVC Pipeline (dvc repro)    ← trains the model end-to-end
    ↓
Run Model Tests                 ← quality gate (R² ≥ 0.50)
    ↓
Promote Model to Production     ← only on main branch
    ↓
Run FastAPI App Tests           ← verifies /predict and /metrics endpoints
    ↓
Configure AWS Credentials       ← requires AWS GitHub Secrets
    ↓
Login to Amazon ECR
    ↓
Build, Tag & Push Docker Image to ECR
    ↓
Deploy to EKS                   ← kubectl apply, rollout status
    ↓
Prometheus & Grafana Monitor    ← active scraper pulls live metrics from EKS
```

### Required GitHub Secrets

| Secret | Purpose |
| :--- | :--- |
| `CAPSTONE_TEST` | DagsHub access token (MLflow auth) |
| `AWS_ACCESS_KEY_ID` | AWS IAM credentials |
| `AWS_SECRET_ACCESS_KEY` | AWS IAM credentials |
| `AWS_REGION` | AWS region (e.g. `us-east-1`) |
| `ECR_REPOSITORY` | ECR repository name |
| `EKS_CLUSTER_NAME` | EKS cluster name for deployment |

> The AWS and EKS steps are gated with `if: github.ref == 'refs/heads/main' && success()` and are silently skipped until the secrets are configured.

## Docker

The `Dockerfile` uses `python:3.12-slim` as the base image.

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY app/ ./app/
COPY params.yaml .
COPY models/ ./models/     # populated by dvc repro in CI before docker build
EXPOSE 8000
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

The `models/` directory is copied at build time. In CI, `dvc repro` runs before `docker build`, so `models/` is always populated. The `CAPSTONE_TEST` token is passed at runtime as an environment variable — never baked into the image.

**Build locally:**
```bash
docker build -t uber-fare-app:latest .
docker run -p 8888:8000 -e CAPSTONE_TEST=<your_token> uber-fare-app:latest
```

Visit `http://localhost:8888`.

## Kubernetes Deployment

**File:** `deployment.yaml`

Defines a `Deployment` (1 replica) and a `NodePort` Service on port 30080.

```bash
kubectl apply -f deployment.yaml
kubectl get pods
kubectl get svc
kubectl port-forward svc/uber-fare-service 9000:8000
```

Visit `http://localhost:9000`.

On real AWS EKS, change `type: NodePort` to `type: LoadBalancer`. AWS will provision an Application Load Balancer and assign a public DNS name accessible via `kubectl get svc`.

### 1. Clone and Install

```bash
git clone https://github.com/RedLordezh7Venom/uberfareMLOPs.git
cd uberfareMLOPs

# Install uv
pip install uv

# Install all project dependencies into a virtual environment
uv sync
```

---

### 2. Configure Authentication

This project uses DagsHub as both the MLflow tracking server and the DVC remote storage. You need a DagsHub access token.

**Get your token:** Log in to [dagshub.com](https://dagshub.com) → Profile → Settings → Access Tokens → Generate.

```bash
# Linux / macOS
export CAPSTONE_TEST=<your_dagshub_token>

# Windows PowerShell
$env:CAPSTONE_TEST="<your_dagshub_token>"
```

Add it to your `.env` file so it persists across sessions:

```bash
# .env  (this file is gitignored — safe to store tokens here)
CAPSTONE_TEST=<your_dagshub_token>
```

---

### 3. Pull the Data

The raw dataset is stored on DagsHub S3, not in Git. Pull it with DVC:

```bash
dvc pull data/raw/uber.csv.dvc
```

This downloads `data/raw/uber.csv` (~22MB) from the remote. You only need to do this once — DVC caches the download locally.

---

### 4. Run the Full Pipeline

```bash
dvc repro
```

DVC runs only the stages whose inputs have changed since the last run. On a clean clone it runs all six stages:

```
Running stage 'data_ingestion'...
Running stage 'data_preprocessing'...
Running stage 'feature_engineering'...
Running stage 'model_building'...
Running stage 'model_evaluation'...
Running stage 'model_registration'...
```

After completion you will have:
- `models/model.pkl` — trained model
- `models/scaler.pkl` — fitted scaler
- `reports/metrics.json` — R², RMSE, MAE
- A new experiment run visible on your [DagsHub MLflow dashboard](https://dagshub.com/RedLordezh7Venom/uberfareMLOPs)

---

### 5. Start the API

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Open `http://localhost:8000` in your browser. The map UI lets you drop pickup and dropoff markers and returns a fare prediction.

Alternatively, confirm the API is responding:

```bash
curl http://localhost:8000/metrics    # Prometheus metrics
```

## Simulating EKS Locally with Floci

For local EKS practice without an AWS account, use [Floci](https://floci.io) — a free, MIT-licensed AWS emulator that runs real k3s clusters via Docker.

```bash
# Start Floci
docker run -d --name floci \
  -p 4566:4566 -p 5100:5100 -p 6443:6443 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  floci/floci:latest

# Set fake credentials
export AWS_ENDPOINT_URL=http://localhost:4566
export AWS_ACCESS_KEY_ID=test
export AWS_SECRET_ACCESS_KEY=test
export AWS_DEFAULT_REGION=us-east-1

# Create EKS cluster (Floci boots a real k3s container)
aws eks create-cluster \
  --name uber-fare-cluster \
  --region us-east-1 \
  --role-arn arn:aws:iam::000000000000:role/eks-role \
  --resources-vpc-config subnetIds=subnet-00000001

# Connect kubectl
aws eks update-kubeconfig --name uber-fare-cluster --region us-east-1

# Deploy
kubectl apply -f deployment.yaml
kubectl port-forward svc/uber-fare-service 9000:8000
```

## Key Design Decisions

**DVC for data, Git for code.** Raw data and processed artifacts are never committed to Git. DVC tracks them via `.dvc` pointer files. This keeps the repository lightweight and makes every pipeline run reproducible.

**Lifespan-based model loading.** The FastAPI app loads the model and scaler inside the `lifespan` context manager rather than at module import time. This prevents DagsHub OAuth from being triggered during test collection, which would hang the CI runner waiting for browser input.

**Environment-aware authentication.** All scripts use a consistent pattern: if `CAPSTONE_TEST` is set (CI), use token-based auth. If not (local development), fall back to DagsHub's interactive OAuth. No code changes are needed between environments.

**Quality gate before promotion.** The model must pass R² ≥ 0.50 on the held-out test set before `promote_model.py` is called. This ensures only validated models reach Production in the MLflow Registry.

**Metrics in the image, secrets at runtime.** The Docker image contains the baked-in model artifacts for fast startup. The `CAPSTONE_TEST` token is injected at runtime via environment variable — it never appears in the image or the repository.
